Diferencia entre restricción de BD y validación en Java: 
La BD protege siempre los datos independientemente de la aplicación que se conecte; la validación en Java ofrece una mejor experiencia de usuario con mensajes claros antes de viajar a la base de datos. Se complementan.

¿Qué ataque evita PreparedStatement? 
Evita la inyección SQL al tratar los parámetros estrictamente como valores de datos y nunca como código ejecutable. No protege contra nombres de tablas/columnas dinámicos ni exime de validar la lógica de negocio.

¿Qué es una transacción y qué garantía ACID se comprobó? 
Es un conjunto de operaciones que se ejecutan todas en bloque o ninguna. El test de producto inexistente/fallo comprueba la atomicidad.

Problema de abrir una conexión por método: 
Conectar es una operación costosa en tiempo y recursos de red/servidor; la solución estándar es utilizar un pool de conexiones (como HikariCP) para reutilizar conexiones ya abiertas.

# Informe de Evidencias · ej01: Mi servidor de base de datos

## Paso 1 · Predicciones iniciales

1. **Si paras el contenedor con `stop` y lo arrancas con `start`, ¿se conservan los datos?**
   - **Respuesta:** Sí, los datos se conservan. El comando `stop` solo detiene la ejecución del contenedor, pero su estado y los volúmenes asociados permanecen intactos en Docker. Al hacer `start`, la base de datos vuelve a arrancar tal y como estaba.

2. **¿Y si usas `down -v`?**
   - **Respuesta:** No, los datos se pierden. El comando `docker compose down` elimina los contenedores y la red, y el indicador `-v` (volumes) destruye explícitamente los volúmenes de almacenamiento persistente asociados, formateando la base de datos a su estado inicial.

3. **¿Por qué el puerto del `docker-compose.yml` empieza por `127.0.0.1`?**
   - **Respuesta:** Por motivos de seguridad. Mapear el puerto a `127.0.0.1:3306` (loopback / localhost) garantiza que el servidor MySQL solo acepte conexiones entrantes desde la propia máquina local y no sea accesible públicamente desde otras máquinas de la red local o internet.

## Paso 4 · Tu primera consulta

Resultado devuelto al ejecutar `SELECT VERSION(), CURRENT_USER(), DATABASE();` en DBeaver:

- **`VERSION()`**: Devuelve la versión exacta del servidor MySQL instalado (por ejemplo, `8.0.35` u `8.4.0`, según la imagen Docker utilizada).
- **`CURRENT_USER()`**: Devuelve el usuario con el que te has autenticado y la IP desde la que conecta, por ejemplo: `root@%` o `dwes@%`.
- **`DATABASE()`**: Devuelve el nombre de la base de datos activa seleccionada en la conexión, que en este caso es `tienda`.
